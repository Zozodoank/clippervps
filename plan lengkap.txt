## Fase 2 — Anggaran sampling 240p @50 frame/menit (konfigurasi saja, tanpa kode)
`.env` server (nilai baru, semuanya sudah punya normalizer yang mendukung):
```
RENDER_SAMPLE_INTERVAL_SEC=1.2      (50 f/menit; clamp min 0.5 aman)
VLM_ORACLE_FRAME_HEIGHT=240          (clamp 240..720 — pas di batas bawah)
VLM_ORACLE_MAX_FRAMES=500            (plafon pool; tidak di-clamp, aman)
VLM_ORACLE_AUDIT_MAX_FRAMES=240      (plafon maksimum klamp — ok)
GK_MAX_BATCH_FRAMES=500              (cap agregat gatekeeper, jangan 240 lagi)
SAMPLE_MAX_FRAMES=500
VLM_ORACLE_TOTAL_TIMEOUT_SEC=1800    (600 TIDAK cukup utk 500 frame — lihat hasil bench: 500 f ≈ 18 mnt lokal)
VLM_ORACLE_TIMEOUT_SEC=300           (per batch grid: 8 gambar×4 frame butuh lebih lama dari 1 frame)
```
⚠️ Bukti terukur kemarin: gatekeeper 2,35 s/frame ⇒ **kalau Gatekeeper ikut menganalisa semua frame, 500 frame = ±20 menit**. Rekomendasi: biarkan Gatekeeper tetap pada cap 240 (subsample merata) dan oracle yang makan 500 — tambahkan catatan di test `gatekeeperPipeline` bila perilaku ini diuji.

## Fase 3 — Grid 2×2 untuk pengiriman Oracle (setelah Fase 1 terbukti)
Prinsip desain: **grid adalah kendaraan angkut, kontrak vonis tidak berubah** — `perFrame[].index` tetap index frame asli; pemetaan sel dilakukan server.

1. **`server/utils/frameGrid.js` (baru, pure function)** — `planGrids(frames, cells=4)` → `[{ gridPath, cells:[{index,sceneIdx,timestamp}], ... }]` row-major. Diuji unit penuh tanpa FFmpeg.
2. **Menjahit gambar via FFmpeg** (bukan library Node baru — tidak ada sharp di proyek): fungsi `composeGridImages()` di `vlmOracleService.js` memakai FFmpeg yang sama seperti `extractFrames` L372: input image2 sequence → `-vf tile=2x2`, + `drawtext` angka sel bila font tersedia (fallback: tanpa label, prompt menegaskan urutan row-major). Grid 852×480 **tidak tersentuh** `MAX_SIDE=1024` notebook → detail per frame tetap ~130 token (sesuai hitungan kita).
3. **Payload claim** (`vlmOracleRoutes.js` + builder batch): item batch = grid dengan field baru `cells:[index...]`; `url` menunjuk file grid. Route serving hanya menambah entri allowlist (pola sudah ada).
4. **Prompt** (`vlmGateService.buildVlmPrompt` varian oracle / promptBuilders): "Jawab perFrame untuk SEMUA index yang tertera; gambar adalah grid 2×2 baris-demi-baris."
5. **Normalisasi vonis** (`normalizeOracleVerdict` + `applyOracleVeto`): entri `perFrame` di-distribute ke frame asli via `cells`; index tak dikenal → dibuang; sel tanpa vonis → dianggap BELUM terverifikasi (semantik STRICT tidak dilonggarkan). Recovery single-image notebook tetap bekerja tanpa perubahan berarti.
6. **Env**: `VLM_ORACLE_GRID=2` (0/1 = kirim terpisah — jalur lama tetap ada sebagai fallback darurat), masuk `FLAG_NORMALIZERS` + snapshot.
7. **`kaggle/deploy.ps1` / notebook**: HANYA perlu update bila `protocolVersion` dinaikkan — naikkan konstanta dan terima keduanya sementara (notebook lama = kirim terpisah, tidak ada paksaan restart sesi).
8. Test: `vlmOracleGrid.test.js` (grouping, distribusi vonis, vonis parsial, sel hilang STRICT), update fixture `vlmOracle.test.js`, `vlmOracleFlags`/configSnapshot untuk `VLM_ORACLE_GRID`.

## Fase 4 — Zone-classifier MobileNetV3 pengganti DBNet (jalur independen)
1. **Dataset distilasi**: `server/gatekeeper/make_zone_text_dataset.py` — jalankan DBNet atas `gatekeeper/dataset/` + `add_watermark_frames.py` → label 5 zona (bawah/atas/4 sudut) per frame crop.
2. **Training**: `train_zone_text.py` (turunan `train_scene_filter.py`), satu backbone MobileNetV3-S + 5 kepala sigmoid (dijalankan per-crop 224), augmentasi blur/JPEG-low-quality meniru 240p. Ekspor `models/zonetext_v1.onnx` + entry `download_models.py`.
3. **Integrasi `service.py`**: `GK_TEXT_BACKEND=dbnet|zonemob|sobel` (default tetap `dbnet` sampai zonemob tervalidasi); kelas path baru di `TextGatekeeper` dengan output bentuk sama (`suspicious, total_cov, bottom_cov, reason, cornerActivations`) → warisan stride & tracker sudut tidak berubah.
4. **Pengiriman ke HP**: `sync-to-termux.ps1`步骤 5 hanya men-scp `*.gguf` — perlu diperluas ke `*.onnx` (atau handalkan `download_models.py` di perangkat).
5. **Validasi ukur**: jalankan ulang `scratch/bench_gk.sh` (sudah terbukti jalan) → target: stage text < 100 ms/frame; total ±1 s/frame ⇒ 250 frame ≈ 4 mnt. Test Python setara `test_face_policy.py` + `gatekeeperPipeline.test.js` sisi Node (kontrak respons tidak berubah).

## Risiko & mitigasi
| Risiko | Mitigasi |
|---|---|
| Mode kalibrasi dipakai diam-diam untuk produksi | Flag beku di snapshot + `jobMeta.oracleCalibration` + badge di riwayat job client; auto-run menolak kalibrasi (hanya explicit env) |
| Model 3B salah mengikat sel grid | drawtext nomor sel + instruksi row-major eksplisit + sel tanpa vonis = BELUM terverifikasi (STRICT tidak melonggarkan) + jalur fallback `VLM_ORACLE_GRID=0` |
| Retry job lama mencampur mode | `configSnapshot` sudah membekukan `ORACLE_OFFLINE_CALIBRATION` & `VLM_ORACLE_GRID` per-job |
| Distilasi mewarisi blind-spot DBNet | Review manual 200 sampel acak + augmentasi sintetis; DBNet tetap selectable via env |
| drawtext tanpa font di proot/Termux | Deteksi filter saat runtime → fallback grid tanpa label (prompt row-major) |
| Kontainer HP berisi kode lama | Fase 0 `git pull` sebelum apa pun |

## Alternatif yang ditolak (dan kenapa)
- **Set `VISION_VERIFY_MODE=legacy`** untuk mematikan Kaggle → gerbang stage1Render secara desain MENOLAK mode itu (mandate 2026-10); melawannya sama dengan menghapus kebijakan.
- **Matikan total Gatekeeper lalu lihat output** → tidak menghasilkan "filter" apa pun; output = tanpa kurasi sama sekali, tidak bisa dibandingkan.
- **Stitching grid pakai sharp/jimp di Node** → dependensi native baru di dua lingkungan (Windows + Termux); FFmpeg sudah ada dan sudah dipakai frameExtractor.
- **Kontrak notebook baru khusus-grid (`protocolVersion` tunggal)** → memaksa seluruh sesi Kaggle di-upgrade serentak; desain mapping di server membuat vonis tetap kompatibel.
- **PP-OCRv5_mobile_det / CRAFT pengganti DBNet** → tetap pipeline segmentasi+post-processing berat (bukan akar masalah 741 ms/frame) / lebih berat.
- **Mengganti wajah YuNet** — sudah Anda lakukan (SCRFD); hanya diverifikasi ulang di Fase 0.
